# Dashboard Finances

Учебный монорепозиторий для практики Python backend и подготовки к собеседованиям.

## Как вести занятия

- Общайся по-русски. Перед шагом объясни, что изучаем и зачем, покажи короткий пример на соседней задаче и дай задание с критериями готовности.
- Используй QuickStart из гайда для обвязки. Части с пометкой «пишешь сам» оставляй Вадиму; помогай подсказками и ревью. Пиши ключевую логику за него, только если он явно об этом попросил.
- На ревью сначала разбери поведение и тесты, затем свяжи решение с вопросами собеседования. В устной практике задавай по одному вопросу.
- Каждый учебный шаг веди отдельной веткой и PR в `main`. Перед началом сверяй прогресс с кодом и историей Git.

## Устройство и проверки

- `cabinet/`: Django/DRF, личный кабинет и Celery. Настройки разнесены по окружениям; миграциями управляет Django. HTTP и права проверяются во view, валидация и представление данных — в serializer, бизнес-сценарии и транзакции — в сервисах там, где нужна отдельная логика.
- `collector/`: FastAPI, SQLAlchemy, Alembic, Redis и отдельный воркер. Разделяй внешних клиентов, репозитории, сервисы и HTTP. Границу транзакции определяет вызывающий код; кэш инвалидируется после успешного коммита.
- Оба сервиса используют Python 3.13 и собственные `pyproject.toml` и `uv.lock`. Команды `uv` запускай из каталога нужного сервиса. Для установки используй `uv sync --locked`.
- Локальное окружение описано в `docker-compose.yml`. Если `.env` отсутствует, создай его из `.env.example`. `make up` поднимает сервисы, `make migrate` применяет миграции, `make logs` показывает логи.
- `make check` запускает Ruff, mypy и pytest для обоих сервисов. Для изменений одного сервиса запускай релевантные проверки из его каталога. Для работы с моделями сверяйся с проверками миграций в `.github/workflows/ci.yml`. Тесты с БД требуют PostgreSQL; внешний HTTP в тестах подменяй.
